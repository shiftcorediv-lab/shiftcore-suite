# AI Handoff

ClaudeとCodexの間で、作業指示書・レビュー・承認済み文書・完了記録を共有するフォルダです。

## 新しいセッションを始めるとき

**`SESSION_HANDOFF.md` を最初に読んでください。** 役割分担、現在地、次にやること、判断待ちの項目がまとまっています。

## 常設の参照文書

| ファイル | 内容 |
|---|---|
| `SESSION_HANDOFF.md` | セッション引き継ぎ。役割分担と現在地 |
| `ISSUES.md` | 課題ID一覧と状態 |
| `AUDIT_20260801_ShiftCoreSuite全体.md` | 全課題の根拠となる監査報告 |
| `AUDIT_20260801_ShiftBuilder棚卸し.md` | ShiftBuilder単体の棚卸し |

## フォルダ

| フォルダ | 用途 |
|---|---|
| `inbox/` | Claudeが作成した新規指示書・改訂版の受け渡し |
| `reviewed/` | Codexによるコード照合・レビュー結果 |
| `approved/` | えいちが実装を承認した指示書 |
| `archive/` | 完了済み文書・置き換えられた旧版 |

## ファイル名

既存文書を上書きせず、次の形式を基本とします。

```text
YYYYMMDD_課題ID_短い内容_連番_状態.md
```

課題IDの定義は **`ISSUES.md`** を参照してください。ファイル名に使うIDは、その表に載っているものだけとします。

例：

```text
20260802_G-A_signup認証_01_claude-draft.md
20260802_G-A_signup認証_02_codex-review.md
20260802_G-A_signup認証_03_claude-revised.md
20260802_G-A_signup認証_04_approved.md
20260802_G-A_signup認証_05_result.md
```

## 文書冒頭の状態表示

各文書の冒頭に、必要な範囲で次を記載します。

```md
- 状態: レビュー待ち / 要改訂 / 承認済み / 完了
- 作成者: Claude / Codex / えいち
- 作成日: YYYY-MM-DD
- 前提文書: ファイル名
- 置き換える版: ファイル名、またはなし
- 実装: 未実施 / 実施中 / 完了
- commit: 未実施 / 完了
- push: 未実施 / 完了 / 対象外
- deploy: 未実施 / 完了 / 対象外
```

## 共通ルール

1. Claudeの一時セッション出力ではなく、このフォルダへ最終文書を保存します。
2. 確認済み事実、ユーザー報告、推論、未確認事項を区別します。
3. コード上の主張には、可能な限り根拠ファイルと行番号を付けます。
4. 本番設定や外部サービスの主張には、情報源と確認日を付けます。
5. `approved/` に置かれ、かつ実装依頼が明示されるまで、レビュー文書を実装指示として扱いません。
6. APIキー、IDトークン、パスワード、個人情報などの秘密情報を記録しません。
7. 既存文書を上書きせず、改訂版は新しい連番で作成します。
8. 実行していないテスト、commit、push、deployを完了と記載しません。

## 基本フロー

```text
Claude作成 → inbox
Codex照合 → reviewed
Claude改訂 → inbox
えいち承認 → approved
Codex実装・検証 → archive（結果文書を追加）
```
