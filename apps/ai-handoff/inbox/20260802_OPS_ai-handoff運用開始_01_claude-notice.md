## 1. 決まったこと

えいちの指示により、**Codexとの作業指示書・レビュー・承認記録・完了記録は `apps/ai-handoff/` で管理する。**

これまでのように、Claudeの一時セッション出力（`outputs/`）や `apps/` 直下へ文書を置かない。

正式なルールは **`apps/ai-handoff/README.md`** にある。本書はその運用開始の連絡であり、詳細はREADMEを正とする。

## 2. フォルダとフロー

```
Claude作成 → inbox/
Codex照合 → reviewed/
Claude改訂 → inbox/
えいち承認 → approved/
Codex実装・検証 → archive/（結果文書を追加）
```

| フォルダ | 用途 |
|---|---|
| `inbox/` | Claudeが作成した新規指示書・改訂版 |
| `reviewed/` | Codexによるコード照合・レビュー結果 |
| `approved/` | えいちが実装を承認した指示書 |
| `archive/` | 完了済み文書・置き換えられた旧版 |

## 3. Codexへの依頼

1. **レビュー結果は `reviewed/` へ保存する。** チャット返信だけで終わらせない
2. **実装・検証の結果文書は `archive/` へ追加する**
3. 文書冒頭に、README記載の状態表示ブロックを付ける
4. **既存文書を上書きせず、新しい連番で作成する**
5. ファイル名は `YYYYMMDD_課題ID_短い内容_連番_状態.md`

## 4. 重要：`inbox/` は実装指示ではない

README共通ルール5のとおり、**`approved/` に置かれ、かつえいちから実装依頼が明示されるまで、文書を実装指示として扱わない。**

`inbox/` にある指示書は、えいちの承認を待っている状態である。Codexが読んで照合・指摘するのは歓迎するが、**その段階で実装へ進まないこと。**

## 5. 現在の役割分担

えいちの指示により、次のとおり。

| 担当 | 役割 |
|---|---|
| Claude | **監査役。** 調査、指摘、指示書作成、差分レビュー、検証 |
| Codex | **実装役。** コード変更、テスト、コミット、デプロイ |

Claudeは実装・コミット・公開・GAS反映・戻しにくい操作を行わない。必要な場合はえいちへ確認する。**役割が変わるのは、えいちが明示的に指示したときだけ。**

この分担は好みの問題ではなく、`AI_COLLABORATION_HANDOFF.md` 第5節の「単一writer」原則にもとづく衝突回避でもある。同じチェックアウトを2者が同時に編集すると事故る。

## 6. 記録しないもの

READMEの共通ルール6のとおり、**APIキー、IDトークン、パスワード、個人情報を文書へ記録しない。**

エンドポイントURLやデプロイIDは、既に公開JSに含まれているため記録してよい。
