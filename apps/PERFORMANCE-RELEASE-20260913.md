# 速度改善の公開・確認記録

## 対象

表示の先行化、要求内の共通読込、マスター参照キャッシュ、読取待機の整理。認証・編集権限の緩和、URL変更、追加有料サービスは対象外。

## 変更点

- 勤怠管理は保存済み予定と最新打刻を先行表示し、予定同期は別要求。同期成功後に再表示。
- 出発・最寄り到着は予定の外部同期を保存ロック前へ移動。確定した報告を応答で返し、画面の再取得を待たず次の操作へ進む。
- 通知は現場報告と同一行へ待機状態を保存。既存の5分間隔の定期処理で送信する。本番実行履歴で15:07、15:12、15:17、15:22の実行を確認。遅延・混雑時の5分以内を保証するものではない。
- 実績の共通設定を要求内で再利用。改訂履歴は詳細を開く時に取得。履歴CSVは省略しない。
- オフの純粋な参照4種類を保存ロックから分離。復旧書込みを伴う本人最新希望休取得と提出はロック維持。
- シフトは当月を先行表示。古い月の応答は破棄し、前月と候補者の取得を継続。
- メンバー初期表示の履歴を後読みし、同一初期要求内の名簿を再利用。
- オーダーの登録用・マスター参照結果は30分キャッシュ。更新時に版を変更する。店舗画面の初期3要求を1要求へ統合。
- 同時進行中の本人照合を共有するが、完了した本人情報のキャッシュ期間は延長しない。
- 読取のタイムアウトと応答形式検査を追加。更新の結果不明時の自動再送は追加しない。

## 通知の障害対応

勤怠管理の「通知の要確認」には全期間の失敗、15分を越えた待機・送信中を件数表示する。打刻は保存済みなのでスタッフに再打刻させない。

1. 管理担当が勤怠原本の「現場報告」で `通知状態` が `要確認`、または長時間の `待機` / `送信中` の行を特定する。
2. 定期処理の実行履歴、送信済みメールを確認する。送信途中の失敗は結果が不明なので自動再送しない。
3. 送信済みと確認できれば対象行だけ `送信済み` にする。未送信と確認でき、再送が承認された場合は対象行だけ `待機` に戻す。
4. 次の定期実行と受信を確認する。送信先・内容が不明なまま一括再送しない。打刻日時・場所・本人情報は変更しない。

既存の通知状態が空白の過去報告は配送対象にしない。フロントを戻しても配送済み・待機行は削除しない。
