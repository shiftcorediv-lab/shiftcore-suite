# Another Portal

「会社という街に出勤する」を体験の核にした、ShiftCoreの仮想オフィスです。

> 開発状態: 2026-08-23付で凍結。本番未反映。再開時は [`docs/FROZEN_HANDOFF.md`](./docs/FROZEN_HANDOFF.md) を最初に確認すること。

## プロダクト上の位置付け

- APは社員、店舗、シフト、勤務状態などの正データを管理する。
- Another PortalはAPのデータを使い、会社の人や空気を感じられる体験を提供する。
- 個人用のAI秘書室とは分離する。

## 最初の縦切り

APで出発した利用者がオフィスに現れ、同じ空間にいる社員の状態を確認し、相手を選んで「すぐ話す」または「メッセージを送る」まで進める1画面です。

現時点では体験検証用のローカルプロトタイプです。APの勤怠Outbox、PortalのWebhook受信基盤、AP出勤後の安全な遷移、Firebaseログイン、bootstrap実データ描画まではローカル実装済みですが、WebSocket、音声通話、チャット永続化には未接続です。

## キャラクター・見た目の基準

### 世界観

- 90年代の風変わりな16-bit街RPGを思わせる、見下ろし型表現にする。
- ゲームの達成報酬ではなく、人の存在と話しかけやすさを軽やかに伝える。
- リアルな人物再現は避け、服色、名前、状態で判別できる簡潔なアバターにする。
- 特定作品のキャラクター、ロゴ、地形、家具を複製せず、Another Portal固有の世界として作る。

### 色と質感

- 基調色: 青、紫、黄色、ピンク
- 会話UI: 黒地、白い太枠、色付きの外枠
- 家具: 形と配色に少しだけ違和感を入れた、明るい街の道具
- 輪郭: 小さな画面でも形が崩れない濃色の太線
- 選択: 三角カーソル、段階的な跳ね、短いゲーム調メッセージ
- 影: 平面的なドット絵を保ちつつ、UIとマップの階層が分かる硬い影

### 状態の表現

色だけに依存せず、状態名を常に併記します。

- 緑: 相談できます / オフィス在席
- 黄: 店舗稼働中
- 赤: 作業に集中 / 対応不可
- 将来追加: 休憩、退勤、離席

### スマホでの優先順位

1. 誰がいるか分かる
2. 相手の状態が分かる
3. 相手を選べる
4. 話す方法を選べる

画面下部には主要領域へのナビゲーションを固定し、選択した社員への操作を片手で届く位置に置きます。

## ローカル実行

```bash
npm install
npm run db:generate
npm run dev
```

AP Webhookをローカル確認するときは、`AP_WEBHOOK_SECRET` を実環境とは異なるテスト値で設定します。本番値はソースやローカル設定へ保存せず、ホスト側のSecretに登録します。

bootstrap APIには `AP_ACCOUNT_API_URL` と `AP_ATTENDANCE_API_URL` も必要です。いずれも認証情報を含まないHTTPS URLだけを設定します。

## 次の実装境界

AP連携の詳細は [`docs/AP_INTEGRATION_API.md`](./docs/AP_INTEGRATION_API.md) を参照。

1. AP出発イベントと勤務状態の契約を本番設定へ接続する。
2. WebSocketで在席・状態・移動を同期する。
3. テキストチャットを実装する。
4. 音声通話と文字起こしは権限・保存方針の確定後に追加する。
